The Living Specification — Serve

A supporting spec of live-spec.html, which is the entry point and holds the state; this file exists by its split row there (dl-split-serve). It holds the design of lspec serve: the collection read by people in a browser, with a map and search beside every page. Read it whole when a change touches serve, its sidebar or its launchers; a session maintaining main does not load it. Nothing here is part of operating a spec: seeing the map or a search result is not a read (dl-wholeload). Decisions establish the required behavior stated here; the tool establishes actual behavior, and where they differ the gap is an open item here (P7).

What is served

lspec serve answers on 127.0.0.1 only and builds each page as it is requested: the file from disk, unchanged, with the sidebar added to the response (dl-serve). Every verdict in the sidebar comes from the same Collection the other verbs use, rebuilt per request, so an edit shows on reload and nothing is stored (dl-graphderived). Dotfiles and dot-directories (.git and kin) and any path outside the instance are refused.

When the instance carries lspec.css, it is served in place of the page's stylesheet, so a reader is offline and themed; a light, dark or system choice is remembered in the browser and applied before the page first paints (dl-substrate).

serve.sh and serve.bat, beside lspec.py, run lspec serve --open on a double-click, preferring the repository's .venv. Without a named main, serve takes the one AGENTS.md names; a taken port falls back to a free one.

The sidebar

The header names the collection by its main, with its file count, and the file being read, beside the theme choice; search follows. A drawer at the sidebar’s foot, folded until opened, holds the links outside the collection and the live-spec revision main’s footer records (“source” in live-spec itself) and the basis commit being served.

The collection tree shows main, each file its split rows reach and the row that reaches it, then orphans, files outside the collection and collection problems. An import shows one summary line: its settings and, when tracking, how far behind upstream it was at the last check. Its details open on demand: source and revision, when start last checked upstream, and the live-spec revision it carries counted against this instance’s: the same, or so many commits older or newer (dl-serveimports). The tree folds and unfolds by a labelled button on its heading.

This file’s sections are compact blocks, each stating its words, colored by their role: header, store, registers, decisions, rules or prose, the role being what most of a section’s claims are. The section being read lists its claims by id and opening words, each marked in its own role’s color, outlined when sealed, so one key covers blocks, claims and the edges below; hovering a claim shows it whole, a table row cell by cell under its column headings; hovering another section’s block lists its claims without moving the page (dl-serveblocks). The blocks scroll on their own beneath the header, search, tree and the file’s name, gliding to keep the current claim in view (dl-servepane).

Each depends-on edge touching this file is a line in a gutter left of the blocks: a hollow dot on the dependent, a filled one on what it depends on. An end sits at its claim’s row when that section is open, else at the section’s block; an end in another file reaches that file in the tree, or, with the tree folded, stops in an arrow at the top of this file’s blocks (dl-serverail).

“Current” is the claim under a line just below the top of the window, where a jump lands its target; a claim or section clicked, or a page opened at an anchor, stays current until the reader scrolls (watch-highlight).

Search covers every file of the collection, main included: exact (literal, any case, every word including short claims), which searches as you type, or semantic (ranked with find’s model), which searches on Enter (dl-servesearch). A result jumps to its claim, carrying the query to the next page. A clear button in the box, or Esc, empties it and closes the results.

Out of scope (this file)

Editing through the browser, live reload, and serving beyond this machine are out of scope: the server shows the files and the tool’s verdicts, and every change still goes through the session protocol and its gate (the session protocol).
