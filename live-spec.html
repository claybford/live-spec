The Living Specification

A document pattern for advancing one technical design across many separate, stateless AI chat sessions: the document, not the conversation, holds the whole state of the work, and each session loads it, advances it, and writes it back. It applies to any solution type (the type mapping) and to either regime — a thing still converging toward done, or one already running and maintained.

Status: live-system, maintained (dl-selfregime) — this document is applied and follows its own pattern; its indexed external artifact is the file's git history (dl-snapshots).
Locked: the four cornerstones / eighteen principles (Cornerstones I–IV); the HTML + water.css substrate; the two-regime framing; git as the sole record (dl-snapshots).
Open: none in the core; [ADAPT] slots resolve in the reader's instance, not here (dl-noopen).
Top risk: drift-by-accretion — this document out-growing its own compression rules (anti-patterns, dl-twohomes).
Last full sweep: 2026-07-05 — from git's latest audit: commit (P14).
To start a new spec: copy the seed verbatim. To audit one: run the session protocol.

What this is: a methodology spec — it teaches the principles, conventions, and structure that let a long-lived design document act as durable project memory for an AI that has none.

Conventions (canonical homes in parentheses): the whole file is the load unit — keep it lean (dl-wholeload). Every value lives in one canonical home, or is an indexed authority pointing at the artifact that holds it (P1, P7). Status tokens: confirmed / provisional / locked / open / watch (P5). Git is the sole record: content changes and audit events are commits, a clean full sweep an empty audit: commit (dl-snapshots). Decision cells ≤ 40 words (dl-twohomes); each commit is one typed line pointing to rationale, never restating it (P16). Session protocol: load the whole file → make one move → write back to the one canonical place → reconcile the touched node's one-hop neighbors → make one commit (the session protocol).

The Minimum Viable Version & the Seed

Four devices are load-bearing from day one; missing any one is what causes a multi-session effort to fall apart:

  1. A bootloader line (P14) — a cold session orients instantly.
  2. A canonical store (P1) — values cannot drift.
  3. A status vocabulary with provisional values (P5/P6) — trust is legible and work is not blocked.
  4. A decision log with rejected alternatives (P11) — settled choices stay settled.

Add the scope fence (P12) the first time a session derails into a non-goal, the sweep (P8) the first time a conclusion blocks on one unknown, and the de-drift pass (P2) once restatement creeps in. In the live-system regime, promote the ruled-out register the first time a session re-proposes an eliminated cause, and the diagnostic register the second time the same failure is diagnosed; the seed carries the directive slot from day one — fill it with a real stance the first time a session routes around a problem instead of fixing it.

The Problem This Solves

A non-trivial design — hardware, software, a process, an agent, a project — is too large for one sitting and returns across many separate conversations, possibly with different models. Keeping the design "in the chat" fails the moment the conversation ends. Treat the document as the program's state and the AI as a stateless function over it: each session loads the state, transforms it, and writes it back. (A live, running design may be indexed rather than contained — the two-regime framing, P1.)

Why multi-session AI is a distinct problem

The editor is a capable, confident collaborator with no memory of the last edit and a strong prior toward generic patterns. Five consequences drive the methodology — stated once here; every later "why" leans on them.

Statelessness. A fresh session carries nothing forward, so the artifact must be sufficient to reconstruct the entire state — not a supplement to memory but the whole of it.

Whole-file load. Every session reads the entire artifact — a session that skips sections plans on false state — so length is a per-session cost and brevity is a first-class property; anchors exist so edits and references land on the right element, not so reading can stop early (dl-wholeload).

Fresh-context pattern-matching. A new session eagerly applies the textbook frame and does not carry the hard-won reasons for not doing those things; unwritten rejections get re-litigated every session. This is the most AI-specific pressure and the reason the decision log and scope fence outweigh their human-doc counterparts.

Drift under rotating editors. A value living in five places will be diverged by five sessions; the only safe number of copies is one.

Confident fabrication. Asked for a number it lacks, a model supplies a plausible one; provisional markers with provenance let a later session tell measured fact from placeholder.

Two regimes: forward design vs. live system

A forward design converges an unbuilt thing toward a buildable spec: "confirmed" only accrues, and the convergence vocabulary (sweeps, final-vs-pending, measure-then-commit, lock the irreversible first) is built around that arc. A live, deployed system you maintain makes the artifact durable operational memory instead. The live-system regime has five regime differences, the source of every live-system extension in this document (plus one regime-neutral addition, P18):

  • The document indexes the state; it does not contain it. The running system is canonical for values; the document is the rationale layer over it and can go stale — authority runs document ← artifact, and the resolution rule is "fix the document" (P1, P7).
  • "Confirmed" is not monotonic. The environment moves underneath the design. Demotion is event-triggered: the fact gains a minimal [WATCH] marker; the event, date, and re-verification condition live in a watch entry in the open list (P5, dl-watchreg).
  • Unknowns are often not yours to close. Externally-owned blockers pair a locked workaround with a watch and a tombstone flagged for deletion when the external trigger fires (P9).
  • Settled diagnoses need protecting, not just settled choices. Maintenance is mostly debugging; disproven causes get their own register (P17).
  • Maintenance gains a diagnostic register. Recurring failures earn a symptom · tell · fix row beside the ruled-out register; a forward design has no use for one.

The regime is orthogonal to the domain: any column of the type mapping can be either, and a design crosses from the first regime into the second the day it ships. The live-system items switch on once the thing exists and runs; until then they stay dormant.

The Four Cornerstones

Eighteen principles, grouped into four jobs the document must do: a rule and why it holds for an amnesiac editor. Principle numbers are stable anchors, not section-order labels: P17 and P18 are live-system additions placed under Cornerstone III (dl-pnum).

Cornerstone I — One canonical state, zero drift

P1 · Single source of truth

Rule: every value lives in exactly one canonical place; everything else links to it. Why: a duplicated fact diverges under a memoryless editor; the only safe number of copies is one. Live-system: the store may be an indexed authority over an external artifact instead of holding the value — the artifact is canonical, the document can be stale, the fix is to the document (the two-regime framing, P7).

P2 · DRY, enforced as maintenance

Rule: treat restatement as a defect and remove it deliberately — but never merge near-duplicates that encode a real boundary (requested vs. granted, internal vs. wire); state one as a delta of the other (dl-nearcopy). Why: prose copies of canonical values diverge silently; de-drift is real work, not cosmetics.

P3 · Addressability & navigation

Rule: give every claim a stable anchor, link densely, provide a TOC. Why: a reference is only useful if it can be followed, and an edit must land on the right element.

P4 · Self-documenting conventions

Rule: write the document's editing rules inside the document, each as an objective, mechanically checkable condition. Why: the next editor is a fresh model; a convention that turns on judgment ("log material edits") is applied differently every session and decays (dl-gate).

Cornerstone II — Uncertainty is first-class and workable

P5 · A fixed status vocabulary

Rule: label every fact and decision from a small closed set (e.g. confirmed / provisional / locked / open). Why: without explicit status a session over-trusts placeholders or re-opens settled choices. Live-system: "confirmed" is not terminal — an event demotes it to watch; the inline marker stays minimal and the metadata lives in the watch entry (two regimes).

P6 · Provisional-but-actionable, with provenance

Rule: never leave a needed unknown implicit — either a flagged working value with provenance, cited inline and linked to the item that closes it, or mark it open with what would close it. Why: a blank blocks downstream work; a silent guess corrupts it; provenance lets a later session judge and replace.

P7 · Authority hierarchy & honest inconsistency

Rule: declare a ranked authority order up front; surface known contradictions rather than hide them. Why: conflict resolution becomes mechanical, and a flagged discrepancy cannot be "fixed" in the wrong direction. Live-system: the running artifact outranks the document.

P8 · Parameterize over unknowns; split final from pending

Rule: compute gated results as functions of the open measurement (sweeps) and mark which results are already final. Why: honest progress before unknowns close; the sweep collapses to a number the moment the measurement lands. Live-system siblings: ship a workaround now with a watch and tombstone when the unknown is externally owned (P9); build a structural mitigation — an engineered guard, not a predicted number — where a value cannot be made final.

P9 · The open list is a dependency graph

Rule: record what each open item gates; order action by it; take no irreversible step before the measurement that governs it. Why: ungated, the open list is worked in arbitrary order — and an irreversible step taken before its governing measurement is the one error no later session can undo. Live-system: externally-owned blockers resolve on a third party's action — pair each with a locked workaround, a watch, and a tombstone; a workaround kept post-fix because it is more robust is a legal resolution.

Cornerstone III — Settled decisions are protected

P10 · Layered commitment

Rule: lock the irreversible structural decisions first and say so; let detail layers stay fluid beneath the lock. Why: re-opening the foundation is the most expensive thing a framework-hungry fresh session can do.

P11 · Decision log — choice, rejected alternative, reason

Rule: log each decision with the alternative it beat and the reason. Keep the log current-state: a superseded row is removed, its position surviving in the successor's rejected/replaced cell; the transition belongs to git (dl-current, P16). Why: the log answers a re-proposed alternative before it is argued, and makes reversal deliberate.

P12 · Scope fence / non-goals

Rule: state what is out of scope and which critiques do not apply. Why: converts a recurring derailment into a one-time statement; negative prompting for the design.

P13 · Partition proven from novel; lead with risk

Rule: separate reused/proven subsystems from the genuinely new work; name the single biggest open risk up front; cite existence-proofs honestly ("someone did something like this" is not "this is done"). Why: attention concentrates where the danger is, and not on the proven layer.

P17 · A ruled-out-hypotheses register (live-system)

Rule: keep a register of investigated-and-disproven causes, separate from the decision log: what was tested, what ruled it out, where the real cause lives. Its sibling is the diagnostic register — confirmed recurring failures, one symptom · tell · fix row each. Why: a disproven diagnosis has no chosen counterpart, so the decision log cannot hold it — and fresh sessions re-propose it exactly as they re-propose rejected alternatives.

P18 · A prime directive — positive prompting (live-system origin; regime-neutral)

Rule: state, once and at the top, the single stance that governs how every edit is made — the positive complement to the scope fence. Why: pre-empts the strongest fresh-model default, the local shim that routes around a problem instead of resolving it.

Cornerstone IV — Reconstructable and auditable

P14 · A bootloader line

Rule: open with a few sentences giving lifecycle stage, what is locked, what remains, and the top risk — present-tense state only. Change notes and derivation narrative live in git and the decision log, never up top (dl-nohist); the tense tell decides placement: state is present-tense, history is past-tense. The bootloader is a derived view — the one sanctioned restatement — so regenerate it whole from its named canonical sources on each pass; a clause with no source is promoted or deleted (dl-bootloader). Why: a cold session orients in one paragraph instead of re-deriving "where are we."

P15 · Show the reasoning and the tooling

Rule: include the governing logic (equations, contracts, rules) and point to the executable model, not just conclusions. Why: a session that can see how a number was produced recomputes instead of trusting a stale figure.

P16 · Typed, disciplined commit messages

Rule: every session-event is a git commit — the boundary rule, stated once, is every session-event is a commit; a clean sweep is an empty one. Gate on the objective binary — did something happen this session (is there a commit, empty or not) — and type each message from a small closed set: a content change is a normal commit typed from that set; a defect-fixing sweep is a normal commit typed audit:; a clean full sweep is an empty commit (git commit --allow-empty) typed audit:. Each message is one typed line recording the transition and pointing to rationale, never restating it (dl-snapshots). Why: the trail stays complete under rotating editors, and rationale duplicated into a commit is a stale copy.

The Session Protocol

The cornerstones describe the static artifact; this loop operates it. A fresh session can be told simply: "follow the session protocol."

  1. Load. Read the whole document — it is the load unit (dl-wholeload). Orientation priority: the bootloader, the canonical store, the open list, the decision log, the scope fence; in the live-system regime also the prime directive and the bootloader's last-sweep line; before proposing causes in debugging work, the ruled-out and diagnostic registers.
  2. Advance — one legal move:
    • Close an unknown: replace a provisional value with a measured one, re-bucket its status, collapse any sweep it gated (P6, P5, P8).
    • Make a decision: move an item from open to locked; write the rejected alternative and reason into the log (P11).
    • Recompute: re-run the logic/model when an input changed; never hand-edit a derived figure (P15).
    • Extend scope: add structure, then immediately fence what it does not cover (P12).
    • De-drift / audit: collapse restatements to pointers (P2); re-derive the bootloader and every roll-up whole (P14); run the grep-shaped checks — the structural subset (anchor resolution, duplicate ids, count checksums, over-cap cells) is executed by live-spec-validate.py, a red result blocking the commit; the semantic ones (body-instead-of-git change narrative; commit-message narrative) stay human judgment (dl-twohomes, dl-validator). An audit pass removes or relocates in the core; it never elaborates.
    • Flag an event: when the world under the document moves and you witnessed it, place minimal [WATCH] markers on what the event puts in question and file the watch entries (event, date, re-verifies-when) in the open list. Witnessed fallout is enumerable: flags, never a sweep (dl-sweeptrigger).
    • Full sweep: reconcile the whole document against itself and any indexed ground truth; commit it — an empty audit: commit when clean. It is owed only on unenumerable suspicion — when what-might-be-wrong cannot be listed, the only honest scope is everything: (a) a defect of a neighborhood-check edge type found where no recent edit touched — evidence a past session's check silently failed; (b) an edit that landed out-of-band of the protocol; (c) live-system, advisory at Load: an unwitnessed period past the horizon, if the instance sets one. If the sweep cannot run in the session that incurred it, post a sweep-owed entry to the open list (what was found, what it gates, resolves when a sweep lands as an audit: commit). Enumerable suspicion never obliges a sweep; the triggers say when one is owed, not when one is permitted — an elective sweep is always legal and takes an audit: commit (dl-sweeptrigger).

  3. Write back. Update the value in its one canonical place only (P1), then run the neighborhood check on every touched node — part of what touching something is. Edge list [ADAPT — tune per domain]:
    • inbound — every referrer still holds;
    • outbound — cited rows still say what it assumes; gated items exist; every linked anchor resolves;
    • copies — no stale restatement survives;
    • counts — every count checksum over a set the edit changed still matches (dl-counts);
    • status — the node's own tag is still right;
    • indexed artifact (live-system) — it still matches the external artifact it indexes (P7).
    A neighbor changed by the fixes owes the same check; a neighbor verified unchanged ends the follow-up. Finish with one commit — a clean sweep is an empty audit: commit (P16). The artifact is the new state; discard the conversation.

Verification is reference-following: it catches only defects that break a reference. A drift class that breaks none gets a rule that wires one — counts for silently dropped items, git history for lossy moves and retrojected entries, whole-view re-derivation for fossil clauses (dl-counts, dl-snapshots, dl-bootloader).

The discipline: changes are surgical and logged, the canonical store is touched in exactly one place, every touched node's neighborhood is reconciled, and rationale is preserved rather than re-derived.

For software, several cornerstones map to established practice — the decision log is ADRs, the typed commit history mirrors Keep a Changelog, the gated open list is a traceability matrix, P15 is the spirit of literate programming; the contribution here is the synthesis into one artifact tuned for a stateless, pattern-matching editor. That editor's forgetting is a widely worked problem, and the same devices recur wherever it is worked independently — a repo-root file taken as canonical project state (AGENTS.md and kin), a curated, always-reloaded memory bank, the named “clean-slate juror” re-litigation that P11, P12, and P18 pre-empt. The pattern also has recognized kin in the specification literature itself: its live-system regime is the in-service / maintained-as specification, and its executable, always-current character is Specification by Example's "Living Documentation" reached from the stateless-editor side. The regime is orthogonal to every column: a scoped project is the forward regime, a continuous program is the live-system regime, and the maintenance regime adds the five differences of the two-regime framing to whichever column applies.

Anti-Patterns

The direct inverses of the cornerstones (no store, no fence, no bootloader, untyped commits…) follow from the cornerstones; this table names the non-obvious failures.

Substrate Notes — the format is load-bearing, not packaging

Granular addressability. HTML gives arbitrary id anchors on any element — table rows, spans, list items — which is what the dense reference web (P3) runs on. Markdown anchors only headings natively; the swap quietly discards a property the method depends on.

One file, renders identically anywhere. The artifact passes between humans and stateless sessions with no tooling and navigation intact. "Self-contained" scopes to the state; presentation is externalized to one stylesheet dependency and degrades gracefully to plain semantic HTML offline (dl-substrate).

Git is the memory of the memory. A living spec lives in version control: git is the sole record of the document's own past (dl-snapshots), so every content change, audit event (a clean sweep an empty audit: commit), and verbatim claim is checkable rather than asserted.

The conventions are executable. The structural checks (P4) — anchors resolve, no duplicate ids, count checksums, cells within cap — run as live-spec-validate.py (standard library, no browser); the artifact stays tooling-free to read, the validator being optional maintenance automation like git, not part of the state (dl-validator).

Classless CSS is Cornerstone I applied to styling. water.css externalizes presentation to one line, so every session spends its attention on content rather than a bespoke stylesheet it must read, preserve, and avoid breaking. This page ships only the water.css link — no custom block — the same principle taken to its limit, matching the seed.

Net: the principles say what state to hold; the substrate is part of how to hold it. Changing the carrier "for convenience" is a content decision in disguise.

Out of scope (this document)

Tooling specifics (which editor, which AI client, retrieval chunking) and team-collaboration mechanics (locking, concurrent-edit merging) are out of scope — this is the document pattern, not a workflow product. Critiques premised on "just use a database / issue tracker / project-management tool" miss the point: the value is a single human- and AI-legible artifact that is the design's state. Nor does the document argue for or evidence its own adoption: its remit is to teach and operate the pattern — seed a new spec, audit an existing one — not to justify it.
