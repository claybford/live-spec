The Living Specification — Background

A supporting spec of live-spec.html, which is the entry point and holds the state; this file exists by its split row there (dl-split-background). It carries exposition no session protocol move crosses into: how the pattern maps across solution types, the non-obvious failures, and why the format is load-bearing. Read it whole when adapting the pattern to a new domain; a session maintaining main does not load it.

Generalizing Across Solution Types

Nothing in the cornerstones is specific to mechanical engineering: the "unknowns" and "sources" change form; the structure is identical. The mapping beyond hardware is by analogy, exercised most concretely on the software/config side.

For software, several cornerstones map to established practice — the decision log is ADRs, the typed commit history mirrors Keep a Changelog, the gated open list is a traceability matrix, P15 is the spirit of literate programming; the contribution here is the synthesis into one artifact tuned for a stateless, pattern-matching editor. That editor's forgetting is a widely worked problem, and the same devices recur wherever it is worked independently — a repo-root file taken as canonical project state (AGENTS.md and kin), a curated, always-reloaded memory bank, the named “clean-slate juror” re-litigation that P11, P12, and P18 pre-empt. The pattern also has recognized kin in the specification literature itself: its live-system regime is the in-service / maintained-as specification, and its executable, always-current character is Specification by Example's "Living Documentation" reached from the stateless-editor side. The regime is orthogonal to every column: a scoped project is the forward regime, a continuous program is the live-system regime, and the maintenance regime adds the regime differences of the two-regime framing to whichever column applies.

Anti-Patterns

The direct inverses of the cornerstones (no store, no fence, no bootloader, untyped commits…) follow from the cornerstones; this table names the non-obvious failures.

Anti-patternWhat it breaks
A stated count with no link to the enumeration it countsThe set changes and the count silently lies; a retained count checksum detects a dropped item when the enumeration shrinks (dl-counts).
Filing a disproven diagnosis as a decision-log "rejected alternative," or not recording itA dead end has no chosen counterpart, so it is lost; the elimination is re-run (P17).
Treating the document as canonical for values it only indexes from a live systemAn edit "fixes" the wrong layer; the running artifact is silently overridden (P1/P7).
Resolving a source contradiction silently, or attributing only one sideThe losing reading returns unattributed and is re-fought; the resolution cannot be re-judged when a source changes (P7, dl-contradict).
Pre-emptively dating every confirmed value ("confirmed as-of…" everywhere)A document-wide drift surface with no payload; caveat metadata belongs in watch entries (dl-watchreg).
Editing a node without reconciling its one-hop neighborhoodReferrers assert falsehoods that surface sessions later, detached from the causing edit (the session protocol).
Leaving a workaround in place after upstream fixes the cause, with no tombstoneDead scaffolding accretes; sessions maintain a fix for a problem that no longer exists (P9).
Merging near-duplicates that encode a real boundaryDe-drift erases a real distinction (internal vs. wire, requested vs. granted) (dl-nearcopy).
A bespoke, heavy stylesheet on the artifact itselfTaxes every session's context and invites breakage; presentation is a single externalized source too (the format).
A supporting spec with no split row at its parentNobody can say whether main should absorb it, so it accretes; the collection boundary cannot be derived (P19).
Preloading supporting specs "for context"Load cost with no crossed edge to justify it; the session plans on files its move never touches (dl-collection).
Review acknowledgments (data-rev and kin) in the documentsAn in-file ledger by another name: a per-session reading tax and a drift surface (dl-reviewgit).
A hand-maintained file or ownership manifestA second home for what the files and split rows already state; diverges by the next session (dl-graphderived).
Treating a plain link as a review obligation, or a depends-on link as mere navigationEither every reference owes a review or none does; the typed edge is what makes the load-bearing subset visible (dl-dependson).
Change narrative in the document body instead of gitHistory duplicated out of git becomes a drift surface and a per-session reading tax (dl-twohomes).

The format is load-bearing, not packaging

Granular addressability. HTML gives arbitrary id anchors on any element — table rows, spans, list items — which is what the dense reference web (P3) runs on. Markdown anchors only headings natively; the swap quietly discards a property the method depends on.

One file per spec, renders identically anywhere. A collection is several such files, each whole (P19). The artifact passes between humans and stateless sessions with no tooling and navigation intact. "Self-contained" scopes to the state; presentation is externalized to one stylesheet dependency and degrades gracefully to plain semantic HTML offline (dl-substrate).

Git is the memory of the memory. A living spec lives in version control: git is the sole record of the document's own past (dl-snapshots), so every content change, audit event (a clean sweep empty only when no files change), and verbatim claim is checkable rather than asserted.

Classless CSS is Cornerstone I applied to styling. water.css externalizes presentation to one line, so every session spends its attention on content rather than a bespoke stylesheet it must read, preserve, and avoid breaking. This page ships only the water.css link — no custom block — the same principle taken to its limit, matching the seed.

Net: the principles say what state to hold; the substrate is part of how to hold it. Changing the carrier "for convenience" is a content decision in disguise.
